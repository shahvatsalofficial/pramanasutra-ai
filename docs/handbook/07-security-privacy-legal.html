Security, privacy and legal

Threat model, privacy guarantees, license, trademarks, disclaimers and the legal checks not yet performed for PramanaSutra AI.

Version 0.2.0 · Source: docs/handbook/07-security-privacy-legal.md

Security model#

Assets and threats#

ThreatControlTest
Malicious repository executes code on scanThe scanner only reads files; it never runs scripts, installs packages or spawns processesNo child_process in the CLI
Symlink escapes the scan rootSymlinks are skipped, never followed; symlink roots refusedSymlink test
HTML injection or XSS through file names or textEvery dynamic value is escaped before it enters HTMLXSS and escape tests
Path leakage in shared reportsOnly the base name of the scanned directory is recordedReport test
Resource exhaustionDepth, file-count and file-size limits; partial scans are flaggedLimits documented
Weakened policyFail-closed parser; safety flags cannot be changedPolicy tests
Forged evidenceProvenance field; unverified sources never reach ready; human approval always requiredEvidence tests
Overwriting user skillsinit refuses without --force; symlinked destinations refusedInstaller tests
Prompt injection via project textSkills instruct agents to treat project content as dataSkill text

Not covered#

PramanaSutra is not a vulnerability scanner, not a SAST tool and not a penetration test. It has had no independent security review. Do not rely on it to find security defects.

Privacy#

  • The CLI makes no network requests and has no telemetry.
  • Reports are written to your disk only.
  • Reports contain relative file paths and rule text, not source excerpts.
  • When you use the skills, your AI IDE's provider processes prompts and code under the provider's own terms. PramanaSutra does not control that.
  • .env.example documents only optional future settings; no secret is read by the CLI.

Compliance statements deliberately not made#

No claim of SOC 2, ISO 27001, GDPR, HIPAA, PCI-DSS, SLSA level or OpenSSF score is made. Standards are referenced as inspiration, never as conformance.

Reporting a vulnerability#

Use GitHub private vulnerability reporting on the repository, or open a minimal public issue that asks for a private channel without exploit details. See SECURITY.md.
